# Setting Up Inbound Emails

EmitMail includes a high-performance **Inbound SMTP Receiver** capable of receiving incoming mail over Port 25, verifying sender authentication, running spam heuristics, and forwarding structured JSON payloads directly to your application's webhooks.

---

## 1. How Inbound Routing Works

When a third party sends an email to an address on your domain (e.g., `support@yourdomain.com`), the sending mail server resolves your domain's MX record and connects to your EmitMail server on **Port 25**:

```text
[ Remote Mail Server (e.g., Gmail) ]
               │
               ▼ (SMTP Port 25 TLS)
  ┌─────────────────────────┐
  │ EmitMail Inbound Server │  ◄── Accepts raw MIME stream
  └────────────┬────────────┘
               │ (Enqueue Job)
               ▼
  ┌─────────────────────────┐
  │ BullMQ Inbound Worker   │  ◄── Verifies SPF/DKIM, parses MIME, scores spam
  └────────────┬────────────┘
               │
       ┌───────┴───────┐
       ▼               ▼
┌──────────────┐ ┌──────────────────────┐
│  PostgreSQL  │ │  HTTP Webhook Target │
│ (Dashboard)  │ │ (Your Backend API)   │
└──────────────┘ └──────────────────────┘
```

---

## 2. Inbound DNS Setup

To direct global mail traffic to your EmitMail server, configure your domain's **MX** and **A** records:

### 1. A Record for Mail Host
| Type | Name | Value | TTL | Proxy Status |
| :--- | :--- | :--- | :--- | :--- |
| **A** | `mail` | `YOUR_VPS_IP` | 300s | **DNS only (Not Proxied)** |

### 2. MX Record pointing to Mail Host
| Type | Name | Priority | Target | TTL |
| :--- | :--- | :--- | :--- | :--- |
| **MX** | `@` (root) | `10` | `mail.yourdomain.com` | 300s |

> **Verification Tip**: Verify your MX record using the terminal:
> ```bash
> dig MX yourdomain.com +short
> # Expected response: 10 mail.yourdomain.com.
> ```

## 3. Configuring Inbound Mailboxes

In the EmitMail Dashboard:
1. Navigate to **Mailboxes** in the navigation bar.
2. Click **+ Create Mailbox**.
3. Specify the local mailbox username and select the domain:
   - Example: `support@yourdomain.com`
   - Example: `billing@yourdomain.com`
   - *Wildcard routing*: You can configure `*@yourdomain.com` to capture all unassigned addresses.
4. Choose whether to enable **Webhook Dispatch** and select your registered webhook endpoint.

## 4. Inbound Webhook Forwarding

When an incoming message arrives, EmitMail's BullMQ inbound worker parses the multipart MIME stream and executes an HTTP `POST` request to your registered webhook URL.

## 5. Webhook Security & Signature Verification

EmitMail signs every webhook request using an HMAC-SHA256 signature generated with your webhook secret. The signature is sent in the `X-EmitMail-Signature` header.

### Verifying Signatures in Node.js / Express

```typescript
import crypto from 'crypto';
import express, { Request, Response } from 'express';

const app = express();
app.use(express.json());

const WEBHOOK_SECRET = process.env.EMITMAIL_WEBHOOK_SECRET!;

app.post('/api/webhooks/inbound', (req: Request, res: Response) => {
  const signature = req.headers['x-emitmail-signature'] as string;
  const timestamp = req.headers['x-emitmail-timestamp'] as string;

  if (!signature || !timestamp) {
    return res.status(401).send('Missing webhook signature headers');
  }

  // Create expected signature using payload and timestamp
  const expectedSignature = crypto
    .createHmac('sha256', WEBHOOK_SECRET)
    .update(`${timestamp}.${JSON.stringify(req.body)}`)
    .digest('hex');

  // Perform constant-time string comparison to prevent timing attacks
  const isValid = crypto.timingSafeEqual(
    Buffer.from(signature),
    Buffer.from(expectedSignature)
  );

  if (!isValid) {
    return res.status(403).send('Invalid webhook signature');
  }

  const { event, from, subject, text } = req.body;
  console.log(`Received incoming email from ${from.email}: "${subject}"`);

  // Respond with 200 OK to acknowledge receipt
  res.status(200).json({ received: true });
});
```

## 6. Inspecting Received Messages in the Dashboard

In addition to webhooks, you can inspect incoming emails directly inside the EmitMail web interface:
1. Navigate to **Inbox** (`/inbox`).
2. Filter messages by domain, mailbox, or status.
3. Click any email to view rendered HTML, raw MIME headers, spam score analysis, and downloadable attachments.
