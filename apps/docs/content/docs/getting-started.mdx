# Getting Started

Before deploying EmitMail, you must establish an infrastructure foundation. Email deliverability relies on strict server reputation, matching reverse DNS records, and open network ports.

---

## 1. Cloud VPS Selection

Most major cloud providers (such as AWS EC2, DigitalOcean, and Google Cloud) permanently block outbound traffic on **Port 25 (SMTP)** for standard accounts to prevent spam abuse. 

To run a sovereign mail transfer server, choose a VPS provider that permits outbound Port 25:

| Provider | Port 25 Policy | How to Enable | Recommended Location |
| :--- | :--- | :--- | :--- |
| **Hetzner Cloud** | Blocked initially for new accounts | Submit support ticket after 1 month or account verification | Falkenstein / Nuremberg (DE), Helsinki (FI), Ashburn (US) |
| **Linode / Akamai** | Blocked by default | Open a support ticket requesting Port 25 unblock for transactional mail | Newark, Frankfurt, Singapore |
| **Vultr** | Blocked by default | Submit a ticket under *Network / Port 25 Request* | New Jersey, Amsterdam, Tokyo |
| **OVHcloud** | **Open by default** | Outbound Port 25 is typically open without ticket requirements | Roubaix (FR), Gravelines (FR), Beauharnois (CA) |

### Minimum Hardware Specifications

- **CPU**: 1 vCPU (2 vCPUs recommended for high-volume queues)
- **RAM**: 2 GB minimum (4 GB recommended if running PostgreSQL and Redis on the same host)
- **Disk**: 20 GB SSD / NVMe
- **OS**: Ubuntu 22.04 LTS / 24.04 LTS or Debian 12

## 2. Unblocking Outbound Port 25

When opening a ticket with your VPS provider to request outbound Port 25 unblocking, provide clear justification to ensure swift approval.

### Sample Support Ticket Template

```text
Subject: Request to Unblock Outbound Port 25 for Transactional Email Infrastructure

Hello Support Team,

I am deploying our self-hosted transactional email service (EmitMail) on server [SERVER_IP] for our verified domain [yourdomain.com].

This server will only send authenticated transactional messages (such as user signups, password resets, and account notifications) to our registered users.

We have established strict anti-abuse practices:
1. All outgoing emails are signed with 2048-bit DKIM keys and verified against SPF and DMARC policies.
2. We maintain automated bounce and suppression list handling.
3. Our server hostname [mail.yourdomain.com] matches our static IPv4 reverse DNS (PTR) record.

Could you please remove the outbound Port 25 restriction for IP [SERVER_IP]?

Thank you,
[Your Name / Team]
```

## 3. Reverse DNS (PTR Record)

A **PTR (Pointer) record** maps your VPS IP address back to your hostname (e.g., `201.18.193.73` → `mail.yourdomain.com`). 

> **Important**: Major inbox providers like **Google (Gmail)** and **Microsoft (Outlook/Hotmail)** will immediately reject or spam-flag emails from IP addresses whose PTR records do not match their forward DNS A records.

1. In your VPS provider dashboard (Hetzner, Linode, Vultr, etc.), navigate to the **Networking** or **Reverse DNS** tab.
2. Set the Reverse DNS for your primary IPv4 address to:
   ```text
   mail.yourdomain.com
   ```
3. Test your rDNS resolution from your terminal:
   ```bash
   dig -x YOUR_VPS_IP +short
   # Output should return: mail.yourdomain.com.
   ```

## 4. Required Firewall Ports

Configure your VPS firewall (`ufw` or provider security groups) to permit the following ingress and egress traffic:

| Port | Protocol | Direction | Purpose |
| :--- | :--- | :--- | :--- |
| **25** | TCP | Inbound & Outbound | Direct SMTP transfer between MTAs |
| **465** | TCP | Inbound | SMTPS (Secure SMTP over SSL/TLS) |
| **587** | TCP | Inbound | SMTP Client Submission (STARTTLS) |
| **80** | TCP | Inbound | HTTP (Let's Encrypt TLS challenge & redirects) |
| **443** | TCP | Inbound | HTTPS (EmitMail Dashboard & REST API) |
| **22** | TCP | Inbound | SSH Administration (Restrict to your IP if possible) |

### Setting Up UFW on Ubuntu/Debian

```bash
# Allow SSH
sudo ufw allow 22/tcp

# Allow Web Traffic for Dashboard & API
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# Allow Inbound SMTP
sudo ufw allow 25/tcp
sudo ufw allow 465/tcp
sudo ufw allow 587/tcp

# Enable Firewall
sudo ufw enable
```

## 5. Domain Name Requirements

You will need an active domain (e.g. `yourdomain.com`) managed through an authorative DNS provider like **Cloudflare**, **AWS Route 53**, or **Namecheap**.

EmitMail supports sending directly from your root apex domain (`yourdomain.com`) or from dedicated sending subdomains (`mail.yourdomain.com` or `em.yourdomain.com`).

Once your VPS is configured and your domain DNS is ready, proceed to [Setting Up the Domain](/docs/domain-setup) to configure SPF, DKIM, and DMARC records.
