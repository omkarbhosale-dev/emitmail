# Setting Up the Domain

Configuring DNS authentication is essential for maximum inbox deliverability. Modern email providers (Google, Yahoo, Microsoft) require cryptographic proof that your server is authorized to dispatch emails on behalf of your domain.

EmitMail provides an automated **5-point verification probe** that scans your DNS zone in real-time.

---

## 1. Add Domain in EmitMail Dashboard

1. Navigate to the **Domains** view in the EmitMail Dashboard (`http://localhost:3000/domains` or your production URL).
2. Click **+ Add Domain**.
3. Enter your apex domain (e.g. `yourdomain.com`) or sending subdomain (e.g. `mail.yourdomain.com`).
4. EmitMail immediately creates a cryptographically secure **2048-bit RSA private/public key pair** dedicated to that domain.
5. You will see a table of required DNS records generated specifically for your server.

---

## 2. Required DNS Records

Add the following DNS records in your domain's DNS manager (e.g., Cloudflare, Route 53, Namecheap):

### 1. Hostname A Record
Maps your mail server hostname to your VPS public IPv4 address.

| Type | Name / Host | Value | TTL | Proxy Status (Cloudflare) |
| :--- | :--- | :--- | :--- | :--- |
| **A** | `mail` | `YOUR_VPS_IP` | Auto / 300s | **DNS only (Grey Cloud)** |

> **Cloudflare Note**: The `mail` hostname **must not** be proxied through Cloudflare (Orange Cloud) because Cloudflare HTTP proxy does not support raw SMTP traffic on ports 25, 465, or 587.

---

### 2. SPF (Sender Policy Framework) Record
Specifies which IP addresses are authorized to dispatch emails from your domain.

| Type | Name / Host | Value | TTL |
| :--- | :--- | :--- | :--- |
| **TXT** | `@` (root) | `v=spf1 ip4:YOUR_VPS_IP ~all` | Auto / 300s |

- `ip4:YOUR_VPS_IP`: Authorizes your VPS IP to send mail.
- `~all` (SoftFail): Informs receiving MTAs that messages not matching this IP should be accepted but flagged for extra inspection during onboarding. You can tighten this to `-all` (HardFail) once fully configured.

If you already have an existing SPF record, merge it by appending your IP:
```text
v=spf1 include:_spf.google.com ip4:YOUR_VPS_IP ~all
```

---

### 3. DKIM (DomainKeys Identified Mail) Record
A public cryptographic key used by receiving mail transfer agents to mathematically verify that the email was signed by EmitMail and was not tampered with in transit.

| Type | Name / Host | Value | TTL |
| :--- | :--- | :--- | :--- |
| **TXT** | `emitmail._domainkey` | `v=DKIM1; k=rsa; p=MIIBIjANBgkqhkiG9w0...` | Auto / 300s |

- **Selector**: `emitmail`
- **Algorithm**: RSA 2048-bit
- The exact public key string `p=...` is displayed in your EmitMail domain details modal. Copy the entire generated string.

---

### 4. DMARC Policy Record
Defines how receivers should handle emails that fail SPF or DKIM alignment, and where to send forensic and aggregate reports.

| Type | Name / Host | Value | TTL |
| :--- | :--- | :--- | :--- |
| **TXT** | `_dmarc` | `v=DMARC1; p=quarantine; rua=mailto:dmarc@yourdomain.com; aspf=r; adkim=r` | Auto / 300s |

- `p=quarantine`: Moves failed emails directly to the Spam/Junk folder. (Use `p=none` for passive monitoring initially, or `p=reject` for strict rejection).
- `rua=mailto:...`: Receives daily aggregate XML reports on delivery performance.
- `aspf=r` & `adkim=r`: Relaxed alignment for SPF and DKIM.

---

### 5. MX (Mail Exchanger) Record
Directs incoming mail servers where to route inbound messages for your domain.

| Type | Name / Host | Priority | Value | TTL |
| :--- | :--- | :--- | :--- | :--- |
| **MX** | `@` (root) | `10` | `mail.yourdomain.com` | Auto / 300s |

---

### 6. Return-Path / Custom Bounces CNAME
Handles SMTP envelope bounces (`MAIL FROM`) under your own domain name rather than a shared generic hostname.

| Type | Name / Host | Value | TTL | Proxy Status |
| :--- | :--- | :--- | :--- | :--- |
| **CNAME** | `bounces` | `mail.yourdomain.com` | Auto / 300s | **DNS only (Grey Cloud)** |

---

## 3. Live Verification in EmitMail

Once the records are added to your DNS manager, click **Verify DNS Records** in the EmitMail Dashboard.

EmitMail queries authoritative name servers directly and validates each record:
- **SPF Check**: Queries `TXT` for apex and verifies `ip4:` inclusion.
- **DKIM Check**: Queries `TXT` at `emitmail._domainkey.yourdomain.com` and parses RSA public modulus.
- **DMARC Check**: Queries `TXT` at `_dmarc.yourdomain.com`.
- **MX Check**: Checks priority and target resolution.
- **Return-Path Check**: Resolves canonical CNAME.

When all probes pass, the domain status immediately changes from `PENDING` to <span className="badge-orange">VERIFIED</span>, enabling authenticated outbound sending and API key generation.
