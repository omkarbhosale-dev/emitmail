Deploying EmitMail takes less than 2 minutes using our official multi-container Docker Compose configuration and pre-built GitHub Container Registry (GHCR) images.

---

## 1. Quickstart Installation (Automated)

The fastest and most reliable way to deploy EmitMail on any Linux VPS is using our idempotent `install.sh` script, which automatically resolves port conflicts, generates cryptographically secure secrets, and boots the GHCR stack:

```bash
git clone https://github.com/omkarbhosale-dev/emitmail.git
cd emitmail
chmod +x install.sh
./install.sh
```

## 2. Manual Installation

If you prefer to configure and launch each component manually:

<Steps>
  <Step>
    ### Clone the Repository
    ```bash
    git clone https://github.com/omkarbhosale-dev/emitmail.git
    cd emitmail
    ```
  </Step>

  <Step>
    ### Create and Populate Environment File
    ```bash
    cp .env.example .env
    ```
  </Step>

  <Step>
    ### Configure Environment Variables
    Open `.env` in your preferred editor (`nano .env`) and update the key host settings:
    ```bash
    # App Version & GitHub Repository
    APP_VERSION=latest
    GITHUB_REPO=omkarbhosale-dev/emitmail

    # PostgreSQL Database Credentials
    POSTGRES_USER=mailuser
    POSTGRES_PASSWORD=changeme
    POSTGRES_DB=maildb

    # Security Keys
    # Must be at least 32 characters
    JWT_SECRET=changeme
    # 64-character hex string (32 bytes) for AES-256-GCM DKIM encryption
    ENCRYPTION_KEY=changeme
    # Internal secret for dashboard 1-click update trigger
    UPDATER_SECRET=changeme

    # Public URLs & Host Port Bindings
    APP_URL=http://localhost:3000
    API_URL=http://localhost:4000
    DASHBOARD_PORT=3000
    API_PORT=4000
    DOCS_PORT=3001
    SMTP_SUBMISSION_PORT=2525
    SMTP_RELAY_PORT=25
    ```

    <Callout type="info" title="Automatic Onboarding Wizard">
      You do not need to configure domain names or VPS IP addresses inside `.env`! When you first log in to the Dashboard at `http://localhost:3000`, an interactive Onboarding Setup Wizard will automatically detect your VPS public IP, prompt for your domain, and auto-provision your 2048-bit DKIM, SPF, DMARC, and MX DNS records.
    </Callout>
  </Step>

  <Step>
    ### Pull Pre-Built GHCR Images and Launch
    ```bash
    docker compose pull
    docker compose up -d
    ```
  </Step>

  <Step>
    ### Complete Initial Setup Wizard
    Navigate to `http://localhost:3000` (or your domain) and log in with your credentials. The Onboarding Setup Wizard will guide you through:
    - Auto-detecting or entering your VPS public IPv4 address.
    - Adding your primary sending domain (`yourcompany.com`).
    - Copying your 2048-bit RSA DKIM public key and checking live DNS propagation.
  </Step>
</Steps>

## 3. Docker Services Overview

| Container Name | Image / Base | Internal Port | Host Port | Role |
| :--- | :--- | :--- | :--- | :--- |
| `emitmail-dashboard` | GHCR Dashboard | `3000` | `127.0.0.1:3000` | Management Web Dashboard & Analytics UI |
| `emitmail-docs` | GHCR Docs | `3001` | `127.0.0.1:3001` | EmitDocs developer documentation platform |
| `emitmail-api` | GHCR API | `4000`, `2525` | `127.0.0.1:4000`, `0.0.0.0:25`, `0.0.0.0:2525` | Express REST API & Inbound ESMTP server |
| `emitmail-worker` | GHCR Worker | — | — | BullMQ queue worker, DKIM signer & direct MX dispatcher |
| `emitmail-updater` | `docker:27-cli` | `9999` (internal) | — | Secure internal sidecar for 1-Click updates |
| `emitmail-postgres` | PostgreSQL 16 Alpine | `5432` | Internal (`mail_net`) | Primary database (never exposed to host) |
| `emitmail-redis` | Redis 7 Alpine | `6379` | Internal (`mail_net`) | Distributed job broker & cache (never exposed) |

## 4. Updates & Upgrades

EmitMail supports two seamless update paths:

### Method A: 1-Click Update from Dashboard UI
When a new GitHub release is published, a notification badge appears in your Dashboard header. Click **"Download & Install Update"** &rarr; **"Update Now"**. The internal `emitmail-updater` sidecar automatically:
1. Pulls new pre-built GHCR images.
2. Synchronizes any new `.env.example` settings non-destructively.
3. Recreates containers without touching user data or secrets.

### Method B: Terminal Update Script
Run the non-destructive updater on your VPS:

```bash
./update.sh
```

To pin to a specific version:
```bash
./update.sh v1.2.0
```

## 5. Reverse Proxy & Domain Routing

Web services (`dashboard`, `api`, `docs`) bind to `127.0.0.1` by default for zero firewall leaks. You can place your preferred reverse proxy (Nginx, Traefik, Caddy, or Cloudflare Tunnel) in front of them:

### Host Nginx Configuration Example

```nginx
# EmitMail Dashboard (e.g. emitmail.yourdomain.com)
server {
    server_name emitmail.yourdomain.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:4000/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

# EmitDocs Portal (e.g. emitdocs.yourdomain.com)
server {
    server_name emitdocs.yourdomain.com;

    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```
