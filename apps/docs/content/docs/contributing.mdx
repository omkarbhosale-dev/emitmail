Welcome to the **EmitMail** open-source contributor guide! EmitMail is built as a cohesive, single-monorepo application powering high-deliverability transactional email dispatch, 2048-bit RSA DKIM generation, and an inbound SMTP mailbox engine.

Whether you are fixing a bug, adding a new feature to the **Backend API**, optimizing the **Background Worker**, polishing the **Cloudflare Kumo Dashboard**, or improving our **Documentation**, this guide will help you get up and running in minutes.

---

## 1. Monorepo Architecture Overview

EmitMail is organized as a `pnpm` workspace containing four applications. The `packages/` directories are workspace scaffolding and are not currently shared implementation packages.

```text
emitmail/
├── apps/
│   ├── api/            # Express REST API, Prisma ORM, Inbound SMTP receiver (Port 2525)
│   ├── worker/         # Decoupled BullMQ delivery engine, direct MX transport (Port 25)
│   ├── dashboard/      # Next.js 16 UI, @cloudflare/kumo design system, React 19
│   └── docs/           # Next.js 16 + Fumadocs documentation engine (Port 3001)
├── packages/           # Workspace scaffolding; currently no shared package implementation
├── docker/             # Production & development Dockerfiles
├── scripts/            # Deliverability tests and queue simulation scripts
└── docker-compose.dev.yml # Local development PostgreSQL & Redis infrastructure
```

## 2. Quickstart: Local Environment Setup

<Steps>
  <Step>
    ### Prerequisites
    Ensure you have installed:
    - **Node.js**: `v20.x` or `v22.x` (LTS recommended)
    - **pnpm**: `v9.x` or higher (`corepack enable && corepack prepare pnpm@latest --activate`)
    - **Docker & Docker Compose**: For local PostgreSQL 16 and Redis 7
    - **Git**: For version control
  </Step>

  <Step>
    ### Clone the Repository
    ```bash
    git clone https://github.com/omkarbhosale-dev/emitmail.git
    cd emitmail
    ```
  </Step>

  <Step>
    ### Install Workspace Dependencies
    Install dependencies across the entire monorepo using `pnpm`:
    ```bash
    pnpm install
    ```
  </Step>

  <Step>
    ### Configure Environment Variables
    Copy the example `.env.example` file to `.env`:
    ```bash
    cp .env.example .env
    ```
    Review the values in `.env.example`. It contains safe placeholders, not production-ready secrets. For local development, `docker-compose.dev.yml` provides PostgreSQL and Redis; set the API and worker connection variables to match that compose file before starting services.
  </Step>

  <Step>
    ### Start Local PostgreSQL & Redis
    Launch the containerized development database and Redis instances:
    ```bash
    pnpm dev:docker
    ```
    Verify that both containers are running healthy:
    ```bash
    docker compose -f docker-compose.dev.yml ps
    ```
  </Step>

  <Step>
    ### Initialize and Seed Database
    Generate the Prisma client, push the schema to PostgreSQL, and seed the default administrator:
    ```bash
    # Generate Prisma Client
    pnpm db:generate

    # Push schema to local Postgres
    pnpm db:push

    # Set INITIAL_ADMIN_PASSWORD in the root .env, then seed the administrator
    pnpm db:seed
    ```
    The initial password must be unique and at least 16 characters. The admin must change it before using protected endpoints.
  </Step>
</Steps>

## 3. Running Services Locally

You can run individual services depending on which part of EmitMail you are developing:

| Command | Service | URL / Port | Purpose |
| :--- | :--- | :--- | :--- |
| `pnpm dev:api` | **Backend API** | `http://localhost:4000` | Express REST API, Inbound SMTP on port `2525` |
| `pnpm dev:worker` | **Delivery Worker** | Console (Background) | BullMQ worker consuming queue & dispatching emails |
| `pnpm dev:dashboard` | **Dashboard UI** | `http://localhost:3000` | Next.js 16 App Router + Cloudflare Kumo components |
| `pnpm dev:docs` | **Documentation** | `http://localhost:3001` | Fumadocs MDX documentation site |

<Callout type="info" title="Initial Admin Account">
Set a unique `INITIAL_ADMIN_PASSWORD` of at least 16 characters in the root `.env` before seeding. Log in as `admin` with that password, then change it before using protected endpoints.
</Callout>

## 5. Contribution & Pull Request Workflow

We follow standard GitHub Flow for all contributions:

### 1. Branching Strategy
Create a descriptive branch from `main`:
- `feat/feature-name` for new capabilities
- `fix/bug-description` for bug fixes
- `docs/page-name` for documentation updates
- `perf/optimization` for performance enhancements

```bash
git checkout -b feat/custom-webhook-headers
```

### 2. Conventional Commit Guidelines
We use Conventional Commits to generate automated changelogs:
- `feat: add support for custom webhook headers`
- `fix: handle 2048-bit multi-chunk DKIM TXT strings in resolver`
- `docs: add contributing guide for backend api and worker`
- `refactor: extract mx resolution logic into dedicated service`

### 3. Verification Checklist Before Submitting a PR
Before opening a pull request, ensure:
1. `pnpm build:api` compiles with 0 TypeScript errors.
2. `pnpm build:worker` compiles with 0 TypeScript errors.
3. `pnpm build:dashboard` builds successfully.
4. `pnpm build:docs` generates all static MDX pages without errors.
5. All environment variables have clear documentation in `.env.example`.
